# 每日同題與無雷分享（2026-11-13，評比第 13 輪；第 14 輪補題庫改版策略與邊界情況）

像 Wordle 一樣：**全世界同一天拿到同一題殘局**。解完（或看了答案）以後，可以把成績分享成一小段「不劇透」的文字或圖片：別人看得到你走了幾步、哪幾步卡住，但看不出答案；點網址就能打開同一天那一題來挑戰。

## 1. 怎麼玩

1. 打開「🍵 一盞茶殘局」，茶單上面多了一張「🌏 每日同題 #編號」。也可以直接開網址 `#/daily`（今天）或 `#/daily/2026-11-13`（那一天）。
2. 解法跟一盞茶的題一樣：輪到你走，對方用 Pikafish 最頑強的應法；走錯了會看到反駁，可以退回重想；提示四層、看答案也都一樣。
3. 解開或看了答案，解完卡會出現這一題的方格和「📤 分享成績」「🖼 成績圖」兩顆按鈕；按「📊 成績與統計」看統計頁。
4. 每天只記**第一次**的結果。之後可以按「再解一次（不改成績）」再練，成績和分享內容都不變。
5. 解題一樣有修為、會算進殘局棋力和「解過幾題」，但**不算一盞茶茶單**，茶單的連續天數、免簽、護天符照舊各算各的。

份量照星期（臺灣日期）：

| 星期 | 份量 | 題型與難度 |
|---|---|---|
| 一、二 | ☕ 一口 | 短殺，難度 3.5 以下（多半 3 步） |
| 三、四、五 | 🍵 一盞 | 短殺或中殺，難度 3.5～5.5（3～6 步） |
| 六、日 | 🫖 一壺 | 中殺或多步的大師收官，難度 5.5～8（4～6 步） |

## 2. 方格怎麼看

每一步一格，從左到右是第 1 步、第 2 步……

| 方格 | 意思 | 色弱模式 |
|---|---|---|
| 🟩 | 這一步一次就走對 | 🟧 |
| 🟨 | 走錯過才走對（用悔棋符收回的不算錯） | 🟦 |
| 🟦 | 這一步用了提示（免費的方向提示、走錯 3 次自動框出關鍵子也算） | ⬜ |
| ⬛ | 從這一步起看了答案 | ⬛ |

設定裡打開「🎨 色弱模式」，App 裡的方格、分享的文字和成績圖都改用右邊那組顏色。方格後面另外用字寫出步數、走錯幾次、有沒有看提示，看不清顏色也讀得出來；讀螢幕軟體會念「第 1 步一次走對、第 2 步走錯過才走對……」。

## 3. 分享格式

按「📤 分享成績」：手機有系統分享（LINE、訊息等）就直接叫出分享選單；電腦或不支援的瀏覽器改成複製到剪貼簿（跳一句「成績複製好了」）。內容固定三行，例如：

- 第一行：`象棋千秋 每日殘局 #1 🍵一盞`
- 第二行：`🟩🟩🟨 3 步・走錯 1 次・沒看提示`
- 第三行：`https://raysonchen2023-cloud.github.io/xiangqi-lab/#/daily/2026-11-13`

其他寫法：用了提示寫「3 步・用了提示」；看了答案寫「3 步・看了答案」（方格從那一步起變 ⬛）；過了當天才補玩，第一行後面加「・補玩」。

按「🖼 成績圖」：產生一張米色小圖（標題、編號、份量、日期、方格、步數那一行），手機用系統分享連同文字一起送出；不能分享檔案的瀏覽器就把圖存成 `xq-daily-編號.png`，文字一樣複製好。

朋友點第三行的網址，App 會直接打開**同一天那一題**；還沒裝 App 的人用瀏覽器也能玩。

## 4. 統計頁

解過任何一天以後，`#/daily/<日期>` 會顯示那天的成績頁：

- 方格與分享按鈕、下一題還有多久（臺灣時間 0:00 換題）。
- 📊 已玩、勝率（沒看答案解開＝贏，用了提示也算贏）、目前連續、最長連續。
- 走錯次數分佈：一次到位、走錯 1、2、3 次、4 次以上、看了答案，當天那一格會亮起來。
- 🗓 前 7 天的題：沒玩過的可以補玩。

連續天數只算**當天**解開的：補玩不算、看答案會歸零；今天還沒玩時，到昨天為止的連續天數照算。

## 5. 同一題怎麼保證

- **只看日期和名冊**：題目由「臺灣日期」（UTC+8，跟手機設定的時區無關）和題目編號算雜湊決定，不用匿名碼、存檔、解過哪些題、棋力。可以出哪些題寫死在程式裡的「名冊」（見第 6 節），所以每支手機算出來都一樣，**離線也一樣**，題庫檔改版也不影響。
- 換日時間是**臺灣時間 0:00**（在別的時區就是別的時刻，例如紐約冬天是上午 11:00）。一盞茶茶單則是照手機本地時間凌晨 4 點換，兩者各自算。
- 每天依份量從名冊那一類題裡挑雜湊最小的一題；前 28 天同份量排第一的題，今天跳過，所以一個月內幾乎不會重複。
- 編號：2026-11-13 是 #1，之後每天加 1。比這天早、或還沒到的日期，網址打開只會說明原因，帶你去今天的題。
- 題目來自一盞茶殘局題庫（目前 621 題，每題都由 Pikafish 深算驗證過），跟茶單同一份，手機下載過就有；目前名冊收了其中 375 題（☕ 一口 123、🍵 一盞 140、🫖 一壺 112）。

## 6. 題庫改版怎麼辦（第 14 輪）

第 13 輪的做法是「每天從題庫檔裡當下符合份量的題挑」，題庫一加題、刪題、改難度，挑到的題就可能變：同一天新舊題庫的手機會拿到不同題，舊網址打開的那天也可能變成別題。第 14 輪改成**名冊只往後加**：

- **名冊**：`m/07dq-daily.js` 的 `DQ.GEN`，每一批寫「從哪天起」和三種份量各有哪些題號。第 1 批（從 2026-11-13 起）就是 2026-11-05 版題庫照份量分好的 375 題，跟第 13 輪上線時挑的題**一模一樣**（測試逐日比對 2026-11-13～2029-12-31 共 1145 天）。
- **題庫加題、改難度、調順序、刪名冊以外的題**：每一天的題都不變。新題要進每日同題，就在名冊最後面加一批，「從哪天起」設在發布後至少 7 天；那天以前的每一天完全不變，那天起新題才加入挑選。產生新的一批：`node xiangqi-lab/tools/daily-roster.js`（會先檢查名冊的題是不是都還在題庫裡，再印出可以貼上的那一批）。
- **題目有錯要下架**：在 `DQ.DROP` 加一筆「題號＋從哪天起」，日期設在未來；那天以前照舊，那天起不再出。**名冊裡的題不能從題庫刪掉**（`test-daily.js` 會擋），不然那幾天會出不了題。
- **手機上的題庫比程式舊**（找不到那天該出的題）：不會偷偷換成別題，而是說「這支手機裡的題庫是舊版」，請玩家連網重新整理。
- **網址的題號不對**：解題畫面網址裡的題號要跟那天名冊算出來的一樣，不一樣就不開，避免拿別題記成那天的成績。

## 7. 邊界情況

| 情況 | 會怎樣 |
|---|---|
| 閏年 | 2028-02-29 有題（星期二，☕ 一口）、號碼照算；2027-02-29、2100-02-29 不是日期，網址打開說看不懂。連續天數跨 2/29 照算。 |
| 跨年 | 臺灣時間 1/1 0:00 換年，號碼接著算（2026-12-31 是 #49、2027-01-01 是 #50），連續天數跨年照算。 |
| 時區 UTC−12、UTC+14 | 同一瞬間三支手機（UTC−12、UTC+14、臺灣）都是同一天同一題；當天解完都不算補玩。 |
| 手機時間快了幾天 | 拿到的是「那幾天後」的題（跟大家到那天拿到的一樣）；分享出去，時間正常的人打開會說還沒到，並提醒可能是手機時間不準。時間調回來後，未來那天的成績照算「已玩」，但不算進目前連續。 |
| 手機時間早於 2026-11-13 | 不出「#0」「#-3」這種號碼；入口卡和每日同題頁都說手機日期好像不對，請把時間設成自動。 |
| 名冊某類題少於 28 題 | 改成跳過最近幾次**真的出過**的題，最多跳到只剩一題：相鄰兩次一定不同、輪著出；某類一題都沒有就用三類合起來；全空才說找不到。 |
| 補玩超過 30 天前 | 「前幾天的題」清單只列 7 天，更早的用網址 `#/daily/<日期>` 一樣能開、同一題、記成補玩，不影響連續天數；幾年後打開還是同一題。 |
| 分享網址格式錯 | 前後空白、全形數字、`2026年11月14日`、`2026.11.14`、`20261114`、`2026-12-5`、後面黏了 `?fbclid=…`、`&utm_…` 都會換成標準網址 `#/daily/2026-11-14` 再開；看不懂的（亂碼、不存在的日期、夾帶 HTML）不開題，畫面上的字也不會變成 HTML。 |

## 8. 隱私

- 成績只存在這支手機（localStorage 的 `m_dqDaily`），每天一筆：題目編號、步數、方格、走錯次數、提示層數、有沒有看答案、是不是補玩、花了幾秒、完成時間。不會自動送出。
- 分享的內容只有：App 名、第幾號、份量、方格、步數、走錯次數、有沒有看提示或答案、網址（只帶日期）。**沒有名字、裝置代號、匿名碼、存檔、著法、題目出處。** 要不要分享、分享給誰，由你自己在系統分享選單決定。
- 解題本身跟一盞茶其他題一樣，如果打開了「📈 匿名送出學習進度」，會送匿名的作答紀錄（題號、對錯、秒數，用來校正難度），詳見隱私說明第 5 項。
- 刪除：跟其他手機資料一樣，用隱私說明最下面的「🗑 刪除這支手機的全部資料」。

## 9. 限制

- 名冊靠人維護：加新的一批要記得「從哪天起」設在發布後至少 7 天；還在跑第 13 輪舊程式的手機（沒更新 App）不認得新的一批，那批生效以後的日子可能跟別人不同。名冊第 1 批跟第 13 輪的挑法完全一樣，所以新舊程式在加新批以前都同一題。
- 「28 天內不重複」是跳過前幾天的第一順位；名冊夠大時（現在每類 112 題以上）一個月內不會重複，很少時改成輪流出（見第 7 節）。
- 手機時間不準時沒辦法對時（App 沒有向伺服器問時間），只能提示把手機時間設成自動。
- 沒有排行榜、沒有線上比較：統計只看得到自己這支手機的。換手機要用「🎒 換手機」把存檔帶過去，統計才會跟著走。
- 從分享網址第一次打開 App 的新玩家，可能先經過開場畫面或下載等待畫面；如果停在首頁，再點一次網址，或到「🍵 一盞茶殘局」點「🌏 每日同題」。
- 成績圖用瀏覽器畫，字型跟著手機；有的 App（例如部分聊天軟體）收到圖片時會把附帶的文字丟掉，這時再按一次「📤 分享成績」送文字即可。
- 公開對照（第 10 節）的限制另外寫在那一節。
- 測試：`xiangqi-lab/tools/test-daily.js`（27 項：行為 25、原始碼比對 2）在模擬手機裡檢查同一天兩支手機（含不同時區）同一題、臺灣 0:00 換日、隔天換題、網址開回那題、分享文字不含著法和名字、Web Share／剪貼簿、統計數字；第 14 輪加了題庫改版（跟第 13 輪逐日比對、加題改難度不變題、新的一批、下架、舊題庫、名冊完整性）和第 7 節的邊界情況。不開瀏覽器，沒有在真的手機上點過。

## 10. 公開對照：任何人都能核對每天的題沒被偷改（第 15 輪）

每日同題的題目是程式照公開規則算出來的。為了讓玩家、家長、老師不用相信開發者的一句話，第 15 輪多放了一份**公開名冊檔**和一支**對照工具**，用公開倉庫裡的程式（`source/`）和資料（`data/`）就能自己重算、核對。

**公開名冊檔 `data/daily-roster.json`**

- 從 2026-11-13（#1）到 2029-12-31（#1145）每天一行：`[日期, 編號, 份量, 題號, 題面雜湊 q, 答案雜湊 a]`，例如第一天是 `["2026-11-13",1,"cup","lk216",…]`。
- 另外記：名冊的每一批（生效日、三種份量各幾題、題號清單的雜湊）、下架清單、整份名冊的雜湊 `rosterHash`、所有日子的雜湊 `daysHash`、挑題規則的文字說明。
- 檔案裡沒有產生時間：同樣的程式和題庫，每次產生的檔一字不差；一天一行，用 git 看歷次版本的差異很清楚。
- **題面雜湊**＝SHA-256(〔題號, 局面 fen, 輪到誰, 幾步殺〕) 的前 16 個十六進位字；**答案雜湊**＝SHA-256(〔主線 line, 應法樹 tree〕) 的前 16 個字。算之前先把 JSON 正規化（物件的鍵照字母排序），題庫檔換縮排、換鍵的順序都不影響。

**對照工具 `tools/verify-daily.js`**（公開倉庫裡在 `source/xiangqi-lab/tools/`；只要 Node.js 20 以上，不用裝套件、不連網）

| 指令 | 做什麼 |
|---|---|
| `node verify-daily.js` | 全部核對：用程式重算名冊檔裡每一天的題號、編號、份量；程式裡的名冊（每一批、下架）跟名冊檔記的一樣；題庫裡那幾題的題面雜湊、答案雜湊跟名冊檔記的一樣。全部對得上印 ✔、結束代碼 0；有對不上的印 ✖ 和哪一天哪一題、結束代碼 1 |
| `node verify-daily.js --date 2026-11-20` | 只看那一天：份量、候選幾題、前 28 天同份量排第一而今天跳過的題、雜湊最小的前 5 題、挑到哪一題、兩個雜湊，再跟名冊檔比 |
| `node verify-daily.js --changes` | 列出名冊的每一批（從哪天起、一口／一盞／一壺各幾題）和每一筆下架 |
| `node verify-daily.js --diff 舊.json [新.json] [--as-of 日期]` | 比對兩版名冊檔：列出新的一批、新的下架、哪幾天的題變了。**只准從新的一批或新的下架生效那天起變**，而且新版發布那天（`--as-of`，預設今天臺灣日期）和以前的日子一天都不准變；同一題的內容雜湊變了也算 ✖（要換題請下架再加新的一批）。檔名可以寫 `git:<版本>`，例如 `git:HEAD~3` |
| `node verify-daily.js --history` | 在公開倉庫的 git 歷史裡，把 `data/daily-roster.json` 的每一版依序兩兩比對（發布那天＝提交日期） |
| `node verify-daily.js --src index.html` | 不用 `source/` 裡的程式，改用已發布的網頁（`index.html` 裡內嵌的那段每日同題程式）重算 |
| `node verify-daily.js --write` | 開發者用：照程式和題庫重產名冊檔 |

其他選項：`--data <data 資料夾>`、`--roster <名冊檔>`、`--json`（印原始結果）。工具會自己找：開發者電腦（`xiangqi-lab/site/data`）和公開倉庫（`source/` 旁邊的 `data/`）都認得。

**擋得住什麼**

1. 偷換過去某天的題：程式重算的跟名冊檔不一樣 → ✖。連名冊檔一起改：`--history` 會發現已經出過的日子變了。
2. 題號不變、偷改題目內容（局面、答案）：內容雜湊對不上，寫出哪一天哪一題。
3. 偷改舊的一批、拿掉下架紀錄、把新的一批或下架的生效日設在已經出過的日子：`--diff`／`--history` ✖。
4. 網頁裡的程式跟 `source/` 不一樣：用 `--src index.html` 拿網頁裡那段重算。

**開發者改名冊的流程**：改 `DQ.GEN`（新的一批，生效日在發布後至少 7 天）或 `DQ.DROP` → `node xiangqi-lab/tools/verify-daily.js --write` → `node xiangqi-lab/tools/verify-daily.js --diff git:HEAD`（確認只有生效日以後的日子變；生效日離今天不到 7 天會提醒）→ 跟程式一起發布。`test-verify-daily.js` 會擋「名冊檔跟程式或題庫對不上」（例如改了名冊裡某題的局面卻沒重產名冊檔）。

**限制**

- 工具證明的是「公開的程式、名冊檔、題庫彼此一致，而且 git 歷史裡已經出過的日子沒變過」。如果有人改寫公開倉庫的 git 歷史，要靠別人自己留的副本或 fork 比對（`--diff 自己留的副本.json`）。
- 手機實際跑的是 CDN、瀏覽器快取裡的那份程式；工具核對的是倉庫裡的。要核對自己手機那份，可以在瀏覽器存下網頁再用 `--src`。
- 名冊檔目前到 2029-12-31，之後要延長（`--write --to 2032-12-31`）。
- 雜湊只取前 16 個十六進位字（64 位元）：要湊出內容不同、雜湊又一樣的題目，大約要 2 的 64 次方次運算，拿來核對發布的內容夠用；它不是數位簽章，不證明是誰發布的（發布者靠 GitHub 帳號和 git 歷史）。
- 名冊檔和工具是第 15 輪新加的，發布以後 `--history` 才有可以比的歷史；公開倉庫的 `source/` 在下一次重產原始碼時才會包含這支工具。
