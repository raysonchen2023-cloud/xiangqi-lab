## 一、入座運鏡

### 做了什麼
手機直式、玩家沒存過視角、這一盤還沒播過時，進園子會這樣：
1. 園子淡入以後，先停在原本「坐著看」的視角（俯角 0、距離 1 倍）**1.8 秒**。這時看得到對面的人、自己的小帥，也看得到園子。
2. 接著用 **0.8 秒**、ease-in-out 平滑移到 topfit（俯角 0.5，距離照 fitZoom 算到格距約 30px）。

| 情況 | 行為 |
|---|---|
| 運鏡中點一下 | 鏡頭先停在玩家眼前的位置，**這一下照常當成點棋盤**，用玩家當下看到的畫面吸附、選子，處理完直接跳到 topfit（不會吃掉這一下） |
| 運鏡中拖曳、捏合、按 ＋／－、點兩下回正 | 運鏡結束，鏡頭交給玩家（不會硬跳回去） |
| 運鏡中按「👁 平視」 | 照舊切成平視，運鏡結束 |
| 系統設了「減少動態效果」（prefers-reduced-motion） | 不運鏡，直接 topfit |
| 存過視角（store parkView）、桌機、橫向 | 不運鏡，跟以前一樣 |
| 同一盤 | 只播一次。App 開著的時候回到同一盤（換頁再回來、切平面棋盤再切回來）不重播 |
| 同一座園子換下一盤 | 新的一盤會再播一次（每盤一次） |

「這一盤」的代號：挑戰電腦用 `cpu:<st.id>`，線上對戰用 `net:<gid>`。其他沒有代號的地方（車輪戰、同桌對弈）改用網址；在這些地方，App 開著期間只播第一次。播過的盤記在 park3d 模組裡的 `INTRO_SEEN`，App 關掉就清空。

### 證據（node 測試，鏡頭用純數學複製）
在 390×844 的手機上：
- 「坐著看」：對面那個人的臉在畫面 y≈52px，看得到；小帥也在畫面裡。
- topfit（距離 0.599 倍）：對面那個人的臉在 y≈−131px，已經出了畫面。這就是 Gemini 說的問題，也是要先停 1.8 秒的原因。
- 運鏡途中每 50ms 檢查一次，棋盤框都在畫面裡，不會晃出去。

## 二、省電模式

### 設定
設定 → ♟ 棋盤 → ⚙ 更多設定 →「🔋 省電模式：自動／開／關」，預設是「自動」，存在 store `pkPower`。下面一行會顯示：
- 園子開著時：`目前：每秒 N 幀・省電 開／關（原因）`
- 園子沒開時（設定頁通常是這樣，因為換頁時園子會拆掉）：`上次在園子：每秒 N 幀・省電 開／關`，數字是離開園子前最近 10 秒的結果
- 這次 App 還沒進過園子：`目前：還沒進過園子`

開著的園子每秒會自己重新判斷一次。改了設定、插上或拔掉充電線，最多 1 秒就跟著換，不用重進園子。

### 「自動」什麼時候開省電（`pwDecide`）
| 條件 | 說明 |
|---|---|
| `navigator.getBattery()`：沒在充電，而且電量 < 20% | Chrome／Android 才有這個 API，iPhone Safari 沒有 |
| `navigator.connection.saveData` | 使用者開了「數據節省」 |
| 手機，而且 `deviceMemory` ≤ 2 | 只看觸控裝置；桌機記憶體小不算 |
| 手機，而且 `hardwareConcurrency` ≤ 4 | 只在有回報 deviceMemory 的瀏覽器（Chrome 系）才算。Safari 不回報記憶體，核數也只是粗估，怕所有 iPhone 都被判成省電，所以 Safari 要 ≤ 2 核才算 |
| 量到畫面偏慢 | 沒省電時，園子淡入 3 秒後開始量。**連續兩段 5 秒平均都低於每秒 24 幀**才算（偶爾卡一下不算）。結果記 3 天（localStorage `xq_pkLowFps`），下次進園子一開始就省電 |

手動「開」一定省電；手動「關」一定不省電，也不管上面這些條件。

### 省電時做了什麼
| 項目 | 一般 | 省電 |
|---|---|---|
| 畫素比 | min(2, devicePixelRatio) | min(**1**, devicePixelRatio) |
| 太陽投影（2048×2048 陰影貼圖，每畫一格都要多畫一遍） | 開 | **關**（`sun.castShadow=false`，陰影那一遍直接跳過） |
| 抗鋸齒（MSAA） | 開 | **關**（只能在建園子時決定；園子開著途中才轉成省電的話，這座園子先不動，下次進園子才關） |
| GPU 偏好 | high-performance | low-power（同上，建園子時決定） |
| 飄落葉 | 飄 | 藏起來、不算 |
| 飄雲、香爐煙、懸浮畫卷、幻影棋客的呼吸濃淡、燈籠火光 | 動 | 停在當下的樣子 |
| 人物閒置晃動（身體起伏、晃腳、轉頭、對手立繪上下浮） | 動 | 停住（勝負動畫照常） |
| 選中的棋子上下跳、將軍紅圈閃爍 | 動 | 抬起不跳、紅圈不閃 |
| **閒置時畫幾格**（`pwGap`） | 每格都畫（60Hz 螢幕＝每秒 60 次） | 閒置 3 秒內每秒 10 格，之後每秒 2 格 |

「在動」的意思（這時就算開省電也每格都畫，拖曳、走子不會卡）：
手指按著、鏡頭還在移動、入座運鏡、走子／吃子動畫、對手伸手、勝負動畫、拉遠看地圖的朱印儀式、盤面剛變（`draw()` 收到不一樣的盤面、選子、將軍後 1.5 秒）、有人說話（泡泡顯示期間）、畫面大小改變。

App 每 1.5 秒輪詢一次就會呼叫一次 `draw()`。只有盤面真的變了才算「在動」，不然閒置永遠省不下來。

閒置時還留每秒 2 格，是為了讓泡泡收掉、換表情、晚到的貼圖還能畫出來，不會整個停住。

### 預期效果
**render 次數**（`tools/test-park3d-power.js` 用跟 `frame()` 同一套 `pwDue`＋`pwGap` 排程模擬）：

| 情境 | 一般 | 省電 | 少畫 |
|---|---|---|---|
| 閒置 60 秒・60Hz | 3600 | 144 | 96.0% |
| 閒置 10 分鐘・60Hz | 36000 | 1224 | 96.6% |
| 閒置 10 分鐘・120Hz | 72000 | 1224 | 98.3% |
| 20 秒裡拖曳 2 秒・60Hz（拖曳中照樣每格畫） | 1200 | 203 | 83.1% |
| 下棋 10 分鐘（每 20 秒走一步、每步動 1.5 秒）・60Hz | 36000 | 4500 | 87.5% |

**每畫一格的工作量**（從程式碼推算，沒有實測）：
- 畫素比 2→1：每格要算的像素剩 **1/4**（devicePixelRatio ≥ 2 的手機，幾乎是所有手機）。
- 關掉投影：少了一整遍 2048×2048 的深度貼圖。場景裡投影的物件（棋子、人、家具）每格都要多畫一次，這一遍整個沒了。
- 抗鋸齒關掉：少了 MSAA 的多重取樣和 resolve。

兩項乘起來估計：閒置時 GPU 工作量大約只剩原本的 **1% 以下**（render 次數 ≈3.4% × 每格約 1/4）。下棋中大約只剩 **3～5%**。實際能省多少電、少發多少熱，要看手機（螢幕、基頻、背景程式也在耗電），要照下面的步驟實測。

### 量測工具
- `window.__PK.perf`（也可以用 `XQPark3D.perf()`）：`{live, fps, frames, renders, idle, span, power, why, mode, aa, pr, lowFps, fps5}`
  - `fps`：近 10 秒平均每秒畫幾格
  - `frames`：近 10 秒動畫迴圈跑了幾次
  - `renders`：近 10 秒畫了幾次
  - `idle`：其中閒置時畫的次數
  - `aa`：這座園子有沒有開抗鋸齒
  - `pr`：目前畫素比
  - `fps5`：最近一段 5 秒的平均（判斷「畫面偏慢」用的）
- `XQPark3D.power()`：`{mode, on, why}`，也就是現在的設定和自動判斷的結果

## 三、開發者用手機實測

### A. 入座運鏡（約 2 分鐘）
1. 手機直式，而且不能存過視角（按過右上角「俯視／平視」就會存 `m_parkView`，之後不再運鏡）。可以手機接電腦、用遠端偵錯執行 `localStorage.removeItem("m_parkView")`，或用沒按過那顆按鈕的新存檔。
2. 進挑戰電腦，等園子淡入，應該是：
   - 先看到對面的人、小帥坐在桌邊，大約 1.8 秒
   - 然後在 0.8 秒內順順地往上、往前拉成俯視大棋盤
3. 再開一盤新的，同樣再播一次。換到首頁再回到同一盤，**不會**重播。
4. 開新的一盤，在運鏡途中直接點自己的炮：要選到炮（就是點下去時眼前看到的那顆），而且鏡頭馬上變成俯視。
5. 運鏡途中按右上角「👁 平視」：要切成平視。
6. iPhone「設定 → 輔助使用 → 動態效果 → 減少動態效果」打開，再進新的一盤：不運鏡，直接俯視。

### B. 看 fps 那一行
1. 進園子下幾步，然後放著不動 10 秒以上。
2. 回到「設定 → ♟ 棋盤 → ⚙ 更多設定」，看「🔋 省電模式」下面那一行：
   - 省電「關」：`上次在園子：每秒 約 55～60 幀・省電 關`（120Hz 的手機約 110～120）
   - 省電「開」、閒置：`上次在園子：每秒 約 2 幀・省電 開`
   - 省電「開」、一直拖曳：每秒幾十幀，畫面要順
3. 用電腦測的話，可以在開發者工具直接看 `__PK.perf`，不用換頁。

### C. 10 分鐘溫度與耗電（A／B 對照）
每一輪的條件要一樣：同一支手機、螢幕亮度固定（關掉自動亮度）、開飛航模式但打開 Wi-Fi、關掉其他 App、手機放桌上不要握著、拔掉充電線、電量 50% 以上（避免手機自己開低電量模式）。

| 步驟 | 省電「關」 | 省電「開」 |
|---|---|---|
| 1 | 設定裡選「關」 | 選「開」 |
| 2 | 記下開始的電量 %、手機背面溫度 | 同左 |
| 3 | 進挑戰電腦，下 3 步後放著不動 10 分鐘（螢幕不要關：設定 → 螢幕 → 自動鎖定 → 永不，測完再改回來） | 同左 |
| 4 | 記下 10 分鐘後的電量 %、背面溫度，看設定頁那一行 fps | 同左 |
| 5 | 兩輪中間讓手機冷卻 10 分鐘 | — |

溫度怎麼量：
- Android：「設定 → 電池」，或撥號 `*#*#4636#*#*` 看電池溫度，或裝 AccuBattery。
- iPhone 沒有讀數，用紅外線測溫槍量背面鏡頭旁邊；沒有測溫槍就用手摸，比較兩輪誰比較燙。

紀錄表：

| 手機 | 模式 | 開始電量 | 10 分鐘後電量 | 耗電 % | 開始溫度 | 結束溫度 | fps 那一行 |
|---|---|---|---|---|---|---|---|
| | 關 | | | | | | |
| | 開 | | | | | | |

預期：省電「開」的耗電 %、溫升都明顯比較少。閒置時 GPU 幾乎不工作，剩下的主要是螢幕本身的耗電。

## 四、限制與之後可以做的
- 抗鋸齒和 GPU 偏好只能在建園子時決定。園子開著途中才轉成省電（例如電量掉到 20% 以下、量到偏慢），這一座園子的抗鋸齒先不動，下次進園子才關。畫素比、陰影、動畫、閒置少畫都是馬上生效。
- iPhone Safari 沒有電池 API，也不回報記憶體，「自動」主要靠「量到畫面偏慢」和 2 核以下判斷。iPhone 使用者如果覺得燙，請手動選「開」。
- 「畫面偏慢」記 3 天。換了新手機或手機升級以後，可以到設定選「關」，或等 3 天過期。
- 下雨、下雪的粒子在省電閒置時會跟著每秒只畫 2 格（看起來比較像定格）。之後如果覺得怪，可以考慮省電時改成靜止的雨絲貼圖。
