## 1. 根因（為什麼下過棋的人會被當成新玩家）

1. **開頭畫面只看「有沒有旅程」**（`m_journey`＝選過角色）。沒有旅程就只畫「⚔ 新的旅程／📱 從舊手機搬資料／📂 讀入存檔檔案」，沒有「繼續」。
   沒選過角色、卻已經在下棋的人，是這樣來的：從深連結（`#/cpu`、`#/canju/…`）進來（開頭畫面會跳過）、自動化瀏覽器（`navigator.webdriver` 會跳過）、
   開發者模式，或在存檔功能上線以後才第一次打開、但先走了別的路。存檔功能上線**以前**的老玩家有過渡（`saveMigrateOld`），之後的沒有。
2. **「先試一手」的判斷沒看下到一半的棋**：`fwNeed` 只看 `m_onboard1、m_xp、xq_record…` 和殘局解開過的題；
   只有一盤沒下完的晉級賽／練功房、或解到一半的殘局，`xq_record` 還沒有東西 → 被當成第一次，新分頁先跳教學。
3. **按「新的旅程」會把進度清掉**：`journeyStart` 不管有沒有旅程都先 `saveApply({})`，把 `JOURNEY_KEYS` 全部刪掉——
   裡面有 `xq_play`（桌上那盤）、`xq_play2`（收著的棋）、`xq_record`（戰績）、`xq_cpuRate`（電腦積分）、`m_cjRun…`（殘局進度）。
   模擬玩家在新分頁走完選角，這些都被清掉；那個分頁記憶體裡還留著那盤，所以當下還看得到「接著下」，之後重開（或另一個分頁重讀）就**整盤消失**。
4. **首頁「🔰 立即開始」的判斷看錯鍵**：`hmNew` 看 `store "record"`（`m_record`），但沒有任何程式寫這個鍵，電腦戰績在 `xq_record`；
   所以只要沒進過新手訓練營，下過幾十盤首頁也是「立即開始」。第 3 點把戰績清掉以後，更是一定變回「立即開始」。
5. **多分頁會互相蓋掉**（見第 4 節）：local.js 的桌上那盤 `P` 每個分頁各一份在記憶體，各自整盤寫回 `xq_play`，後寫的贏。

「選了秦朝角色後首頁地名變成酒肆、學室」：是選角的設計（意見回饋 669：選角＝首頁換成角色家鄉朝代的園子）。
這次不再逼選角，所以「繼續」不會改朝代；自己選角色時，確認畫面會先講「首頁會換成他家鄉朝代的園子」。

## 6. 多分頁

**會互相覆蓋。** 原因在 `xiangqi-lab/src/local.js`：

- 桌上那盤 `P` 在每個分頁的記憶體裡各一份，只在第一次用到時（`ensureP`）讀 `xq_play`；之後每走一步、每評完一步、電腦每落一子都 `savePlay` 整盤寫回。
- 兩個分頁同時開著：A 在下、B 停在首頁。B 在載入時讀到的那盤如果正輪到電腦走，**B 也會替那盤算一步、寫回去**，蓋掉 A 之後下的步；
  B 開了新局（或像模擬玩家那樣在 B 選了角色清掉 `xq_play`），A 再走一步又會把舊盤寫回去。最後留下的是「最後寫的那個分頁」的版本，另一邊的進度就不見了。
- `xq_play2`（收著的棋）、戰績、積分每次都重讀 localStorage，比較不會出事；問題主要在桌上那盤。

**加的保護（最小）**：

1. `playSync`：監聽 `storage` 事件（瀏覽器只送給「其他」分頁）。別的分頁改了或刪了 `xq_play`（或整個 `localStorage.clear()`），這邊就把記憶體裡的 `P` 丟掉，
   下一次 API 用到時 `ensureP` 重讀最新的。正在算的電腦著法回來時 `P` 已經換掉，`playEngine` 原本就會丟掉那步。
2. `analyzePlay`：背景評等改成只寫回「同一盤」；另一個分頁把 `P` 換掉了就停下，不把舊的那份寫回去。`savePlay` 在 `P` 是空的時候不寫。
3. 對局 id 變了（另一個分頁開了別盤或清掉了）發 `xq-play-other`，`07m4-resume.js` 的 `rsOther` 提示一次：「另一個分頁也開著象棋千秋，棋盤已換成那邊最新的一盤。建議只留一個分頁…」。
4. 第 1 節第 3 點（第一次選角清掉進度）修好以後，模擬玩家那種「新分頁選角→舊分頁那盤消失」不會再發生。

5. **版本號（評比循環第 2 輪補）**：`xq_play` 最前面多 `seq`（第幾版）、`tab`（寫的分頁代號）。每個分頁記得自己「知道的那一版」（`VER`）：
   - **寫入前**（`playWrite`）：localStorage 裡現在那一版跟 `VER` 不一樣＝另一個分頁在這之後寫過 → **不覆蓋**，丟掉記憶體那份、記一筆「⛔ 兩個分頁同時下」、發 `xq-play-newer`
     （畫面提示「另一個分頁剛下了一步，已切換到最新」，`07m4-resume.js`），下一次 API 重讀最新的。
   - **動作前**（`playPost` 開頭的 `ensureP`）：每次都比版本，不一樣就重讀；重讀後發現這個分頁上次看到的那盤（`PID`、第 `PN` 手）已經被別的分頁下過或換掉，
     落子、悔棋、認輸、和局、提示這類動作（`PLAY_MUT`）**這一下不算**，一樣提示、回最新盤面。開新局、換盤、↩ 回到那一盤照做（那是明確的意思，跟盤面無關）。
   - 只有另一個分頁寫了「背景評等」（步數沒變）：靜靜重讀、這一步照下，不誤報。
6. **換盤備份**：別的分頁把桌上那盤換成別盤（`storage` 事件的 `oldValue`＝被換掉前的最後一版），這盤沒下完、也不在 `xq_play2` 裡 → 存進 `xq_playBak`（最多 3 盤），
   記一筆「⚠️ 被另一個分頁換盤」，保存紀錄裡那一筆旁邊有「↩ 回到那一盤」（`/play/restore`）。換成別種棋時那盤本來就收進 `xq_play2`，一樣可以 ↩。
7. **崩潰復原**：每次寫新版前，先把舊版原文搬到 `xq_playPrev`。寫入丟例外（空間不足）＝舊版原封不動、`VER` 不變（下一步再試）、記一筆「❗ 存檔失敗」；
   `xq_play` 讀出來壞掉（JSON 斷掉、缺 `moves`）＝改讀 `xq_playPrev` 並寫回、記一筆「🩹 改讀上一份完整存檔」；兩份都壞＝開新的一盤，不當掉。

**還沒處理的**：兩個分頁在**同一毫秒級**一起讀到同一版、又一起寫（瀏覽器之間 localStorage 沒有交易），版本號擋不到，還是後寫的贏——
要完全排除得改用 Web Locks（`navigator.locks`）包住「讀版本＋寫入」，這次沒做（真人幾乎碰不到，測試裡用「寫入當下才撞」那一條驗的是相差一個事件迴圈以上的情況）。
存檔格（`slotCur`）也是兩個分頁共用，A 分頁的自動存檔會存「現在 localStorage 裡的東西」，如果 B 分頁讀了別格，A 會把 B 的內容存進 B 那一格（內容是對的，只是由 A 寫）。

## 7. 怎麼驗（瀏覽器，不用 headless）

1. 開本機 App，設定 → 開發者模式**關掉**（開發者模式不出教學）。在 DevTools Console 模擬「沒選角色、有一盤下到一半」：
   `localStorage.removeItem("m_journey")`、`localStorage.removeItem("m_slotMeta")`，然後從 `#/cpu` 走兩三步（或晉級賽）。
2. **開新分頁**打開同一個網址（首頁）：不應該出「說書人：客官，先試一手」；開頭畫面主按鈕是「▶ 接著下／和冷面國手（晉級賽）的棋・第 N 回合」，
   下面有「🎭 選一位角色，開始故事」。按「▶ 接著下」→ 直接回到那一盤同一步，不跳續局小卡，首頁朝代沒變。
3. 回到開頭畫面（再開一個新分頁），按「🎭 選一位角色，開始故事」→ 選角 → 確認畫面有「你現在的戰績、下到一半的棋都會留著…」→ 出發；
   首頁大按鈕仍是「▶ 接著下」，重新整理後那盤還在（`JSON.parse(localStorage.xq_play).moves.length` 不變）。
4. 只有紀錄、沒有下到一半的棋：主按鈕是「▶ 繼續／回到首頁・戰績和進度都還在」，首頁大按鈕是「♟ 快速對局」不是「🔰 立即開始」。
5. 真的全新（無痕視窗）：仍是「先試一手」；跳過後 menu 是「⚔ 新的旅程」＋「先逛逛，之後再選角色」；選角畫面有「之後再選，先逛逛 ›」。
6. 多分頁：A 分頁在 `#/cpu` 下到一半，B 分頁去朝代擂台開一盤（不同種類）→ A 分頁跳一次提示「另一個分頁也開著…」，棋盤換成 B 那盤；
   A 原本那盤在 `xq_play2` 裡（`JSON.parse(localStorage.xq_play2).cpu`），首頁「▶ 接著下」接得回來；兩邊重新整理後看到的是同一份，不會一邊把舊盤寫回去。
   （同一種棋在另一個分頁開新局＝跟單一分頁一樣換掉舊的；晉級賽照原規矩算中途離開。）
7. 保存紀錄、衝突、崩潰：照第 9 節做。

## 8. 存檔格式（評比循環第 2 輪 ChatGPT 要求）

全部在瀏覽器的 localStorage（`m.html` 的 XQSave 會再鏡像一份到 IndexedDB `xqsave`）。`xq_` 開頭的由 `xiangqi-lab/src/local.js` 寫，`m_` 開頭的由畫面（`store`，`00-util.js`）寫。
「跟存檔格走」＝在 `05b-save.js` 的 `JOURNEY_KEYS`：讀別格、開新旅程時整個換掉；不在的是這支手機的，各格共用。

### `xq_play`：桌上那一盤（跟存檔格走）

```json
{"seq":12,"tab":"k3x9qa1bc","id":"2026-11-11T09-00-00","human":"r","level":3,"rlv":null,"ranked":false,"reward":false,
 "arena":null,"journey":null,"stamp":null,"prize":null,"rk":null,"rate":null,"result":null,"practice":null,
 "hintN":1,"undoN":2,"start":"…","startTurn":"r","noPerp":true,"styleOn":true,
 "moves":[{"f":64,"t":67,"by":"r","q":"正著","loss":0,"ev":30,"bv":30,"bm":"h2e2","bp":["h2e2","h9g7","h0g2"],"rr":null}]}
```

| 欄位 | 意思 |
|---|---|
| `seq` | **版本號**（第 2 輪新加，一定是第一個欄位）：每寫一次 +1。舊存檔沒有＝當成第 0 版 |
| `tab` | **寫的分頁代號**（第 2 輪新加，第二個欄位）：存在那個分頁的 sessionStorage `xqTab`，重新整理不變、每個分頁不同 |
| `id` | 對局編號＝開局時間（`YYYY-MM-DDTHH-MM-SS`，UTC），茶肆盲棋結尾加 `-b` |
| `human` | 玩家執紅 `r`／執黑 `b` |
| `level` | 挑戰電腦的級數 1～18（晉級賽是 0）；`rlv`＝驛站旅人用的段位強度（沒有＝null） |
| `ranked` | 晉級賽（積分挑戰）；`rk`＝開局時顯示的段位；`rate`＝下完後的積分變化 |
| `reward` | 有獎勵的局；`arena`＝朝代擂台的朝代代號；`stamp`＝擂台贏了蓋的章；`prize`＝獎品 |
| `journey` | 石桌往事那一格的代號（`park`、`inn:…`、`char:…`、`bt:…`、章回關卡…），最長 40 字 |
| `practice` | 錯棋重練／練習的資訊（`base`＝起點前擺好的步數、`drill`、`title`…）；不是練習＝null |
| `result` | 結果 `{w:"r"/"b"/null, why, adjudication?}`；還沒下完＝null |
| `hintN`、`undoN` | 這盤用過幾次提示、悔過幾次棋（沒有就不寫） |
| `start`、`startTurn`、`noPerp` | 殘局起手、讓子的關：起始局面、誰先走、關掉長將判負（沒有就不寫） |
| `styleOn` | 秘境棋友這盤有沒有照他的開局喜好走 |
| `moves[]` | 每一步：`f`、`t`＝從哪一格到哪一格（0～89）、`by`＝誰走的；其餘是評等（`q` 評語、`loss` 少幾分、`ev`／`bv` 評估、`bmt`／`pmt` 殺棋訊號、`bm`／`bp` 引擎建議、`bc` 建議著中文、`rr` 對方最佳回應），還沒評就沒有 |

讀的時候用 `stateRebuild` 從 `start`＋`moves` 重建盤面（`board`、`turn`、`repetition` 不存）。

### `xq_play2`：收起來的棋（跟存檔格走）

`{cpu, arena, journey, practice}`，每一種最多一盤，格式同 `xq_play` 但**沒有** `seq`、`tab`、`stamp`、`prize`、`rate`，`result` 一定是 null（下完的不收）。
舊版只存一盤（整個物件就是一盤），讀的時候照 `practice／journey／arena／cpu` 判斷是哪一種。整格都空了就是 `null`。

### `xq_playPrev`：上一版（第 2 輪新加，跟存檔格走）

`xq_play` 被覆蓋前的**原文字串**（每次 `savePlay` 寫新版前搬過來）。只在 `xq_play` 讀不出來時用：改讀它、寫回 `xq_play`。

### `xq_playBak`：被換掉的棋（第 2 輪新加，跟存檔格走）

陣列，新的在前、最多 3 盤；每盤＝`xq_play2` 的格式＋`at`（備份時間）。來源：另一個分頁把桌上那盤換成別盤（沒下完、也不在 `xq_play2`），
或「↩ 回到那一盤」時收納格原本那一盤被擠出來。「↩ 回到那一盤」拿走後就從這裡刪掉。

### `m_resumeLast`：續局記號（跟存檔格走，`07m4-resume.js`）

| 欄位 | 意思 |
|---|---|
| `r` | 最新一份「做到一半」：對局 `{t:"play", k:種類, g:對局 id, n:步數, at:最後動到的時間}`；殘局 `{t:"cj", rk:殘局存檔鍵, id:題號, h:網址, nm:題名, n:步數, at}`；關卡／主題訓練／棋力測驗 `{t:"lv"/"tm"/"qz", rk, id, h, nm, n, N:總步數或題數, at}` |
| `t` | `{對局 id: 最後動到的時間}`（7 天沒動的開 App 時清掉；晉級賽除外） |
| `e` | `{對局 id: 朝代}`＝園子路人那盤是在哪一朝開的 |
| `x` | `[對局 id]`＝「撐過 N 步」已經過關、不再問要不要接續的盤（最多 20） |

盤面本身不在這裡（在 `xq_play`／`xq_play2`／`m_cjRun…`）。

### `xq_saveLog`：對局保存紀錄（第 2 輪新加，**這支手機的**，不跟存檔格走）

陣列，新的在前、最多 20 筆。**不存棋譜**，只有：

| 欄位 | 意思 |
|---|---|
| `at` | 時間（毫秒） |
| `ev` | 事件，見下表 |
| `id` | 哪一盤（對局 id）；選角保留進度時桌上沒有下到一半的棋就沒有 |
| `k` | 種類 `cpu`／`arena`／`journey`／`practice` |
| `n` | 當時第幾手（步數） |
| `rkd`、`ar`、`jn`、`pt`、`dr` | 晉級賽、擂台朝代、石桌往事代號、練習題名、是練習題——畫面拿來寫「練功房・對冷面國手」這種字 |
| `end` | 那時已經下完 |
| `to`、`tk` | 換盤時換成哪一盤、哪一種 |
| `c` | 連續合併了幾次（自動存檔、存檔失敗同一盤連續發生只留一筆，更新時間和步數） |
| `tab` | 哪個分頁記的 |

| `ev` | 畫面上的字 | 什麼時候記 |
|---|---|---|
| `auto` | 💾 自動存檔 | 每次寫 `xq_play`（同一盤連續的合成一筆；第 0 手不記） |
| `reopen` | 🔁 重開後接續 | 這個分頁第一次讀到桌上那盤、而且還沒下完（＝重開 App 讀回來） |
| `take` | 🪟 從另一個分頁接手 | 這個分頁寫的時候，上一版是**別的分頁**寫的同一盤 |
| `swap` | ⚠️ 被另一個分頁換盤 | 別的分頁把桌上那盤換成別盤（多個分頁收到同一件事只記一筆） |
| `gone` | ⚠️ 另一個分頁清掉了桌上的棋 | 別的分頁讀檔、開新旅程、清資料 |
| `clash` | ⛔ 兩個分頁同時下：這邊那一步沒存 | 第 6 節第 5 點兩種情況 |
| `stash` | 📥 收起來（換下別種棋） | 開別種棋，沒下完的這盤收進 `xq_play2` |
| `back` | ↩ 回到那一盤 | 按了保存紀錄裡的「↩ 回到那一盤」 |
| `keep` | 🎭 選角保留進度 | 沒選過角色、有進度時第一次選角（`journeyStart`） |
| `drop` | 🗑 放棄這盤 | 續局小卡按「放棄這盤」（`rsDrop`） |
| `fail` | ❗ 存檔失敗 | 寫 `xq_play` 丟例外（手機空間不夠） |

看的地方：設定頁「💾 存檔」（或行囊的木箱「存檔與讀檔」）→「🧾 對局保存紀錄」（`05b-save.js saveList` → `07m4-resume.js rsLogSheet` → `local.js /play/log`）。

## 9. 兩分頁重現步驟（評審照做）

用電腦版 Chrome 開本機的**離線版** App（`local.js` 只在打包後的版本裡：`node xiangqi-lab/tools/build-site.js` 組出 `site/`，
再 `node xiangqi-lab/tools/serve.js`，開 `http://localhost:8800/xiangqi-lab/`），**同一個網址開兩個分頁**，稱 A、B。
每一步做完可以在 DevTools Console 看 `JSON.parse(localStorage.xq_play).seq`、`.tab`、`.moves.length` 和 `JSON.parse(localStorage.xq_saveLog)`。

**情境一：輪流下，不會互蓋**
1. A：首頁 →「挑戰電腦」（`#/cpu`）開一盤，走兩步（等電腦回）。
2. B：也進 `#/cpu`，看到同一盤同一步；接著走一步。
3. 回 A（不用重新整理）：盤面已經是 B 走過的；再走一步。
4. 兩邊重新整理：看到的是同一盤、步數＝全部加起來。`seq` 一直往上加；保存紀錄有「🪟 從另一個分頁接手」。

**情境二：幾乎同時落子（舊分頁不覆蓋新盤）**
1. A、B 都停在 `#/cpu` 同一盤、輪到你走。
2. A 走一步，**馬上**切到 B（B 畫面還是舊的、不要等它更新），在 B 點另一步。
3. B 跳出「另一個分頁剛下了一步，已切換到最新」，盤面變成 A 那一步，B 點的那步沒有下出去；`xq_play` 的 `tab` 還是 A 的。
   保存紀錄有「⛔ 兩個分頁同時下：這邊那一步沒存，已改讀最新」。
   （「寫入那一刻才撞」——兩個分頁都替電腦算了同一步——手動很難抓時間，看自動測試 `多分頁：兩個分頁都替電腦算了一步` 那一條。）

**情境三：被另一個分頁換盤，再回去**
1. A：`#/cpu` 下到第 4 手以上。
2. B：在挑戰電腦開一盤新的（同一種；或在 B 的 Console 跑 `api("/play/new",{human:"r",lx:5})`），或去「朝代擂台」開一盤（別種）。
3. A：跳一次「另一個分頁也開著象棋千秋，棋盤已換成那邊最新的一盤…」。
4. A：設定 →「💾 存檔」→「🧾 對局保存紀錄」：最上面是「⚠️ 被另一個分頁換盤・練功房・對○○・第 N 手・換成另一盤」，旁邊「↩ 回到那一盤」。
5. 按「↩ 回到那一盤」→ 回到 A 原本那盤同一步；B 開的那盤（下過棋的話）收進收納格，首頁「▶ 接著下」拿得回來。紀錄最上面多一筆「↩ 回到那一盤」。

**情境四：崩潰／重開回到原盤**
1. A：`#/cpu` 下到第 N 手，**直接關掉分頁**（或工作管理員結束 Chrome）。重開 → 開頭畫面「▶ 接著下」（或首頁小卡）回到第 N 手；保存紀錄有「🔁 重開後接續・第 N 手」。
2. 模擬存檔壞掉：Console 執行 `localStorage.xq_play=localStorage.xq_play.slice(0,200)`，重新整理 → 回到上一步的盤面（`xq_playPrev`），保存紀錄有「🩹 存檔壞掉，改讀上一份完整存檔」。
3. 模擬空間不足：自動測試 `崩潰：寫入時 setItem 丟例外` 那一條（瀏覽器裡不好手動塞滿 5 MB）。

**自動測試**（不開瀏覽器）：`node --test xiangqi-lab/tools/test-resume-state.js`——把 `local.js` 整支跑兩份（兩個分頁）共用一個假 localStorage，
storage 事件排隊、測試決定什麼時候送到（不送＝模擬事件還沒到）。涵蓋：交錯落子不互蓋、同時落子不覆蓋（動作前、寫入當下兩種）、換盤備份與 ↩、
清掉不備份、setItem 例外、JSON 壞掉、兩份都壞、保存紀錄的順序／合併／最多 20 筆／不存棋譜。
