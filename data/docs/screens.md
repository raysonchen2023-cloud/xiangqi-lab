# 畫面證據包（怎麼重拍）

回應：評比循環第 15 輪 F1「補可重現畫面證據包」、F2「英文介面截圖與防爆版證明」、X2「連線小卡與星槎說明卡截圖」（評審細項 P41.1、P64.1、P21.2、P45.2、P22.5、P06.3）。

**先說限制：這些截圖都是電腦上的無頭 Chrome（Playwright）模擬手機尺寸拍的，不是實機、不是真人操作。** 每張圖下方都有一條虛線，虛線以下的附註欄是腳本加的（寫明「不是實機」、裝置尺寸、版本號、時間、這張要證明什麼），不是 App 畫面。

## 一個指令重拍

在放專案的資料夾（`myClaude`）下：

```
node xiangqi-lab/tools/qa/evidence-shots.js
```

- 預設拍線上版 `https://raysonchen2023-cloud.github.io/xiangqi-lab/`，任何人裝好 Node.js、Playwright 和 Chrome 都能重拍；大約 8～12 分鐘。
- `--local`：改拍本機組好的版本（用 `xiangqi-db/tools/mhtml.js` 組 `m.html`，自己開本機伺服器，埠 `--port` 預設 8841）。
- `--size pm` 或 `--size se`：只拍一種尺寸；`--only en,fit,net,zh`：只跑某幾段（英文截圖、防爆版檢查、連線小卡、其他繁中功能）。
- `--outdir <資料夾>`：輸出位置，預設 `xiangqi-db/tools/review_loop/rounds/r15`（圖在 `shots/`，manifest 與表格在 `evidence/`）。
- 純函式的測試（不開瀏覽器）：`node --test xiangqi-lab/tools/test-evidence-shots.js`。

腳本只開一個瀏覽器（裡面可以有好幾個分頁），結束或出錯都會關掉瀏覽器和本機伺服器。每個分頁開頁前都把 `xq_netRoot` 設成 `xq_test`，只連測試房，不會進正式大廳；App 偵測到自動化瀏覽器也一律只進測試房。

## 怎麼拍的（哪些不是完全照真人的路）

- **英文介面**：真的點「設定 → 頂欄 🌐 → English」（觸控點擊），App 自己重新載入；之後每頁都在英文模式下拍。讀屏模式是把 `axMode` 設成開再重新載入（等同在設定裡打開「螢幕報讀與鍵盤模式」）。
- **連線狀態小卡**：同一個無頭瀏覽器裡開兩個分頁（各自全新的瀏覽器設定，等於兩支手機），在測試房 `xq_test` 互相邀請（用 App 的 `XQNet.invite`／`XQNet.respond`，跟按邀請、接受是同一條路）、紅方走一步，再真的點訊號膠囊。連不上測試房時改用 App 的渲染函式 `nsgDbgSpec` 帶假資料畫一張，這種圖 manifest 的 `kind` 會寫「示意」，附註欄也會寫「⚠ 示意」。
- **星槎說明卡**：說明卡只在 iPhone（有 `DeviceOrientationEvent.requestPermission`）才會出現。無頭 Chrome 沒有這個函式，腳本在載入前補一個回「不允許」的假函式來模擬 iPhone；說明卡本身是 App 畫的，「🌀 立體」是真的點。
- **每日同題**：成績是腳本寫進存檔的示範紀錄（4 步、走錯 1 次、沒看提示），沒有真的解題；成績頁和分享文字是 App 照這筆紀錄實際產生的。
- **色弱、左撇子**：直接把設定（`cbMode`、`lefty`）打開再進對局頁，等同在設定裡打開開關。
- **預走**：自己走一步後，趁電腦還在想，真的點自己的子、再點落點。

## 英文防爆版檢查怎麼量

英文模式下，首頁、開新局選單、對局頁、結果視窗、設定頁、一盞茶殘局、每日同題，每頁看得到的按鈕、連結、標籤、標題（有視窗或卡片開著時只量最上層那一個；只給讀屏軟體的隱藏區不算），檢查：

1. 文字範圍左右超出元素框超過 1px（上下超過 4px）＝「文字超出元素框」；元素設成隱藏超出的部分＝「文字被截斷」；出現省略號也算截斷。
2. 元素超出父容器（父容器本身可左右捲、元素是浮動定位的不算）。
3. 元素超出畫面（在可左右捲的容器裡不算）；整頁比畫面寬。
4. 兩個元素的文字範圍交疊超過 2×2px＝「文字互相重疊」；文字沒疊、但兩個可點的元素框交疊超過 4×4px＝「按鈕框互相重疊」（容易點錯）。

判斷規則寫在 `evidence-shots.js` 的 `judgeOverflow`，`test-evidence-shots.js` 用假資料逐條測。量的是瀏覽器排版後的位置，看不出「字太小」「顏色太淡」這類問題；附帶列出英文模式下頁面裡還有的中文（含只給讀屏軟體的隱藏標籤；劇情、說明文件、場景標籤本來就還沒翻，見 [英文介面](i18n.md)）。

這支腳本只檢查和回報，不改 App。

## 限制

- **不是實機**：無頭 Chrome 模擬手機的尺寸、像素密度、觸控、安全區，字型是這台電腦（Windows）上的，跟 iPhone 的蘋方、Android 的思源黑體排出來的寬度會有幾個像素的差別；Safari 特有的排版差異也量不到。
- **不是真人**：點擊是腳本送的觸控事件；讀屏播報讀的是 `#axLive` 的文字，不是真的旁白念出來的聲音。
- 線上版要等 App 的 service worker 接手、跨來源隔離生效（App 第一次會自己重新整理），電腦引擎才能走棋；網路慢或 CDN 有狀況時，個別步驟可能失敗，失敗的會寫在 manifest 的 `errors`，不會用舊圖頂替。
- 太頻繁重拍線上版可能被 GitHub Pages 暫時擋（Rate limit exceeded，同一個 IP 的真人手機也會打不開）；腳本偵測到就停，過幾分鐘再跑。
- 第 15 輪拍的時候，停在每日同題（`#/daily/…`）重新載入、也就是冷開每日同題的分享連結，App 開機會出錯（`ReferenceError: Cannot access 'DQ' before initialization`，畫面顯示「畫面沒有載入成功」），之後的英文介面、讀屏模式都不會套用。所以讀屏那張是先回首頁再重新載入；每次重拍都會把冷開連結的結果記在 manifest 的 `notes`，App 修好後那一行就會變成「開機頁面錯誤 0 個」。
- 截圖是當下的版本；之後 App 改版，畫面會跟這裡不一樣，重跑一次就是新版的證據。
