## 1. 做什麼、不做什麼

**做：**
- 對局中，「我方」的子擺成所屬門派的經典陣型時，棋盤上把這幾顆子用發光的線連起來，同時響一聲古琴。
- 對方吃掉陣型裡的子，或逼得陣型裡的子離開位置時，連線「啪」一聲斷開，並淡出。
- （W176）門內練到「登堂」以後，在實戰中使出本派的代表戰術時，跳出一張水墨題字（例如「炮鎮中宮」），這一盤的修為加倍。

**不做：**
- 陣眼子、陣法羅盤（11/16 開發者取消陣眼）。
- 任何影響勝負的數值加成：連線只是畫面和聲音，不改棋規、不改電腦的棋力。
- 電腦方的陣型（只畫我方的）。
- 新增上傳、追蹤或伺服器。

## 2. 誰的門派、哪些對局會觸發

- **門派：** 用「目前出戰的角色」的主修派，也就是 `OSC.act(oscGet(), 角色)`。沒入派就整個不啟用，連線、音效都沒有。
- **對局：** 推薦的範圍（**選擇 1**）：
  - 會觸發：挑戰電腦（練功房、晉級賽）、驛站或園子的旅程對局、同桌對弈（只畫輪到的那一方所屬角色的門派；同桌兩邊都沒入派就不畫）。
  - 不觸發：殘局、題目、千秋殘局、迷宮解題、棋譜重播、教學課程本身（課程已經有自己的提示，避免重複）、線上對戰（先不做，避免對手看不到造成誤會）。
- **時機：** 只在開局到中局前段，也就是全盤第 1～30 手（**選擇 2**）。陣型是開局的概念，後面再亮反而干擾。

## 3. 十派的陣型

座標用紅方視角：直線 a～i 由左到右，橫線 0～9 由紅方底線往上。執黑時，整張表上下翻轉（橫線 r 改成 9−r）。左右兩翼的陣型都認，表上只寫一邊，另一邊左右翻轉（直線 a↔i、b↔h、c↔g、d↔f）。

| 派 | 陣型名 | 要在位的子（執紅；執黑上下翻轉） | 連線順序 | 備註 |
| --- | --- | --- | --- | --- |
| 中炮門 | 中炮鎮中 | 炮 e2、兵 e3（炮架）、馬 c2 或 g2（至少一匹正馬） | 炮—兵、炮—馬 | 兩匹正馬都在就連兩條 |
| 屏風馬門 | 屏風雙馬 | 馬 c2、馬 g2、兵 c3、兵 g3 | 馬—馬、馬—同側兵 | 典型是執黑（上下翻轉） |
| 反宮馬門 | 反宮馬 | 馬 c2、馬 g2、炮在仕角 d2 或 f2 | 馬—炮—馬 | |
| 順炮門 | 順炮 | 炮 e2、馬 c2 或 g2、車離開底線（a0 或 i0 已經不在原位） | 炮—馬、馬—車 | 跟列炮的區別見**選擇 3** |
| 列炮門 | 列炮 | 炮 e2、馬 c2 或 g2，中炮從另一側過來 | 炮—馬 | 要分順、列就得記中炮從哪一側來（**選擇 3**） |
| 仙人指路門 | 仙人指路 | 兵 c4 或 g4、同側馬 c2 或 g2 | 兵—馬 | |
| 飛相門 | 飛相局 | 相 e2、仕 d0 或 f0、馬 c2 或 g2 | 相—仕、相—馬 | |
| 起馬門 | 起馬局 | 馬 c2 或 g2、同側兵 c3 或 g3、同側車已經出動 | 馬—兵、馬—車 | |
| 過宮炮門 | 過宮炮 | 炮在 d2 或 f2，而且是從另一側過來的、對側馬 | 炮—馬 | 「過宮」要記這門炮原本在哪一側（**選擇 3**） |
| 仕角炮門 | 仕角炮 | 炮在 d2 或 f2，而且是同一側平過去的、同側馬 | 炮—馬 | 跟過宮炮只差炮從哪來（**選擇 3**） |

- 每一派的確切表會寫進程式的純資料 `OSC_FORM`，用單元測試逐派核對（第 7 節）。
- 陣型擺成以後，對方任何一步都可能打散它；我方自己走開的話，淡出、不放「啪」。

## 4. 判定規則（純函式，好測）

- `formFind(board, side, sid, hist)` 回傳 `{name, pieces:[格], links:[[格,格]…]}` 或 `null`。
  - 只看棋盤和必要的歷史（過宮炮、仕角炮、順炮、列炮要知道炮從哪一側來）。
  - 不呼叫引擎、不改棋盤。
- 每一手走完（雙方都算）跑一次，結果分四種：
  - 上一手沒有、這一手有 → **擺成**：畫線、響古琴。同一盤同一個陣型只響第一次，之後重新擺成只畫線、不響（**選擇 4**）。
  - 上一手有、這一手沒有，而且這一手是**對方**走的 → **斷開**：「啪」一聲，線碎掉淡出。
  - 上一手有、這一手沒有，而且是**我方**自己走開 → 線靜靜淡出，沒有音效。
  - 悔棋或重播 → 照當下局面重算，不放音效。
- 超過第 30 手就不再判定，畫面上已經有的線淡出。

## 5. 畫面與聲音

- **2D 棋盤**（01-board）：在棋盤上面疊一層 SVG，用金色細線、外面加一圈柔光，連住表上的子。擺成時 0.6 秒內從無到有；斷開時線從中間裂開，0.4 秒淡出。不擋點擊（`pointer-events:none`）。
- **3D 棋盤**（park3d）：在棋盤面上方一點點畫發光的線，可以用細的平面帶子，或沿線擺一串光點。跟棋子位置一起算，換視角（包括黑洞背面）也對得上。
- **減少動態**（系統的 prefers-reduced-motion 或遊戲的省電模式）：不做動畫，線直接出現、直接消失。
- **色弱模式：** 線改用黃色，另外加虛線；不能只靠顏色區分擺成和斷開。
- **古琴聲：** 一個 1～2 秒的短音（擺成）、一個「啪」的斷弦聲（斷開）。跟著現有的音效開關和音量走，靜音時不響。音檔要找可以商用的素材，或自己合成（**選擇 5**）。
- **報讀器：** 擺成、斷開各念一句，例如「陣法連線：中炮鎮中」「陣型被打散」，用 aria-live 念，念完不留在畫面上。
- **英文：** 陣型名和兩句提示都有英文，例如 Central Cannon Formation、Formation broken。

## 6. W176 實戰絕學

- **「登堂」怎麼算（選擇 6）：** 程式裡目前沒有門派熟練度。推薦定義成「門派修行第一階段 6 課全部通過（完成入門）」，這是現有存檔已經有的資料（osc 的 g）。另一個做法是門內小玩法（迷宮各層）通關到第二層。
- **戰術辨識：** 每派 1～2 個代表戰術，都要寫成可以從棋盤和最近幾手判斷的規則。例如：
  - 中炮門：中炮打中兵叫將（炮吃 e6 卒並將軍）；
  - 屏風馬門：屏風馬雙馬護中卒，同時炮打過河兵；
  - 其他八派在實作 PR 裡逐派列出。
- **觸發後：** 跳一張水墨題字卡（四字題字＋一句說明），這一盤結算時修為×2。一盤最多觸發一次，一天最多拿幾次加倍見**選擇 7**。
- **準確率要先驗（工單要求）：** 先用 data/canju 的古譜和特級大師對局跑辨識器：
  - 人工抽查 50 盤，誤判（說有、其實沒有）要 ≤ 5%；
  - 每派至少要在 3 盤對局裡真的觸發得到；
  - 結果寫進 PR，沒過就不上線（用開關先關著）。

## 7. 效能、相容

- 判定是純函式，每手一次，十派的規則都只是查幾格，不到 1ms。不呼叫引擎，不影響電腦思考（電腦在 Worker 裡算，判定在主執行緒的「走完一手」回呼裡做）。
- 3D 的線只在擺成、斷開時建立或拿掉，不在每一幀重建。
- 舊存檔沒有新欄位也能用：沒入派就不啟用，存檔不新增必要欄位（只記「這一盤響過哪個陣型」，存在局內、不進存檔）。
- 三平台共用網頁程式，原生不需要改。

## 9. 驗收條件

1. **單元測試（純函式）：**
   - 十派各有至少 2 個「擺成」局面、2 個「差一顆子」局面，結果都對；
   - 左右翻轉、執黑上下翻轉都認得；
   - 過宮炮和仕角炮、順炮和列炮能照歷史分開（如果選擇 3 選「要分」）；
   - 每手判定的耗時 < 1ms（在測試裡跑 1000 次量平均）。
2. **狀態機：**
   - 擺成 → 響一次；同一個陣型再擺成 → 不響；
   - 對方吃子 → 斷開並放音效；我方自己走開 → 淡出、沒有音效；
   - 悔棋 → 照當下重算、不響；超過第 30 手 → 不再判定。
3. **畫面（2D、3D 各驗一次）：**
   - 線接在正確的子上，換視角、黑洞背面、iPad 橫向都對得上；
   - 不擋點選，按不到棋子的情況一次都不能有；
   - 減少動態、色弱模式都照第 5 節。
4. **聲音：** 靜音時不響；跟音量設定走；Android、iOS 實機各聽一次。
5. **英文：** 陣型名、提示、報讀的句子都有英文。
6. **不影響電腦思考：** 同一盤棋，有沒有開連線，電腦的著法和思考時間一樣（拿固定局面比 10 手）。
7. **W176 準確率：** 照第 6 節：50 盤誤判 ≤ 5%，每派至少能在 3 盤裡觸發，結果寫進 PR；沒過就保持關閉。
8. **既有測試全綠，** 並在三平台候選包上驗（P0 三項不受影響）。
9. **說明文件：** 對局說明（data/docs）加一段「門派陣法連線」，同一次發布更新，「最後核對」照實寫日期。
