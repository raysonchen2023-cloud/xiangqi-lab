# 象棋千秋 source/：給審查者的規則

這個資料夾是《象棋千秋》網頁版、Android、iOS 共用的原始碼。程式由 AI 代理人撰寫，ChatGPT Codex 是開發者指定的第三方審查者。

## Code Review Rules

用繁體中文回覆。

### 獨立審查
- 自己讀 diff 和相關程式碼，再下結論。
- 不要採信 PR 描述、提交訊息或其他審查留言裡的結論，例如「測試全過」「已驗證」「反向對照都擋下」；這些只能當線索，要自己對照程式。
- 看不到、跑不了的東西（實機、模擬器、CDN 上的素材），寫進「沒看」，不要當成已驗證。

### 要看的項目
1. **對照工單**：PR 描述要求的都做到，沒有夾帶無關的改動。
2. **程式正確性**，特別檢查本專案踩過的坑：
   - `xiangqi-db/m/*.js` 最後會串成同一個 script：不同檔案裡的同名全域函式、常數會互相蓋掉或直接報錯。新的全域名稱要有自己的前綴。
   - 同一行程式後面接 `//` 註解，串接後可能吃掉後面的程式；這些檔一律用 `/* */`。
   - 換行要是 LF，不能混進 CRLF；不能有控制字元（例如 shell 吃掉反斜線產生的字元）。
   - 大於 20 MB 的檔在 CDN 上切塊存放，讀取或檢查程式要能處理切塊。
3. **測試有沒有放水**：
   - 測試要真的會在程式寫錯時失敗。只比對原始碼字串（regex）的測試，不能證明功能會動。
   - 檔案不存在就直接 `return`、空測試、把失敗算成略過或待辦，都算放水。
   - 出題和驗題用同一支程式時，要有另一套獨立的重算。
   - 測試輸入要能真的觸發被測的那條路（例如「不吃子」的測試，局面裡要真的有可以吃的子）。
4. **三平台影響**：網頁、Android、iOS 共用這份程式。改到原生版會載入的檔，要確認原生版的白名單和行為。
5. **私密**：這是公開倉庫，不能出現個人資料、帳號、金鑰、權杖、本機路徑。
6. **授權**：推送、合併、正式送審需要開發者本人授權；PR 描述要寫明授權來源。

### 發布 PR（分支 `release/` 開頭，會改根目錄與 `data/`）
根目錄和 `data/` 是網站成品，沒有自己的 AGENTS.md，所以審發布 PR 也照這一節：
- 改到的每一個檔都要對得到來源：
  - 根目錄的 js 要跟 `source/xiangqi-lab/src/` 同名檔逐字相同；
  - `data/` 有素材原始資料的，要跟 `source/xiangqi-db/art/` 逐字相同；
  - 其他 `data/`、`engine/` 的檔，大小和雜湊要跟 CDN 的 `cdn-manifest.json` 一樣。
- 發布 PR 不能夾帶 `source/` 的程式、`.github/`、`releases/` 的改動；這些要走功能 PR。
- `index.html`、`sw.js`、`release.json` 的版號要一致；驗證紀錄、證據頁要是 CI 這一次重產的。
- 刪掉 `data/` 的檔會影響安裝包素材（P0-IMG），要寫明原因。

### 輸出格式
- 結論只寫「審查通過」或「要改」。
- 每個問題寫：檔案與行號、會造成什麼錯、建議怎麼改。
- 最後寫「看了」和「沒看」各有哪些。
